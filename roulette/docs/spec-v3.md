# マグナ抽選ルーレット 仕様案 v3

Claude Design 向けブリーフ。オンラインイベント（クイズ大会・バトル大会）で使う、賞品抽選アプリの仕様。

**v2からの変更点**：抽選の対象を「参加者番号」から「賞品番号」へ全面修正／START・STOPの手動停止方式に変更／賞品プレビュー画面を追加（従来Googleスライドが担っていた役割）。

---

## 1. 目的

オンラインイベントの最後に行う賞品抽選を、画面共有しながら1人で回せるようにする。

1〜75の**賞品番号**をリールで抽選し、止まった番号の賞品を開示する。参加者側に番号はふらない。

**体験のゴール**
- 「何が出るか分からない」まま止めるスリル
- 番号が止まってから賞品が開くまでの、焦らしの時間
- 当たった賞品が一目で伝わる大きな表示

---

## 2. 利用シーン

| 項目 | 内容 |
|---|---|
| 実施形態 | オンライン。**Zoomの画面共有で投影** |
| 操作者 | 1名。キーボードのみで完結 |
| 抽選回数 | 1イベントあたり7〜8回程度（クイズ大会の上位者数に対応） |
| 賞品総数 | 最大75件。当日使うものだけを有効にして回す |
| 端末 | ノートPC（Chrome）。単一HTMLファイルで動作し、サーバー起動を不要とする |

---

## 3. 抽選の流れ

```
① 賞品プレビュー   賞品の一覧を見せる
        ↓
② START           リールが回りはじめる
        ↓
③ STOP            リールが止まり、賞品番号が確定
        ↓
④ 賞品を見る       宝箱が震えて開き、賞品が大きく表示される
        ↓
⑤ 次へ            出た番号はリールから外れる
```

### 3-1. リールの構成

**リールには、まだ出ていない賞品番号だけを並べる。**

こうすることで、STOPを押した見た目の位置でそのまま止められる。裏で抽選し直して滑らせる必要がなく、止めた位置と結果が一致する。抽選が進むほどリールが短くなるため、残りが減っていくことが画面で分かる。

- 停止処理：STOP押下から0.4秒ほどで自然に減速して止まる。停止位置は押した瞬間の見た目に従う
- 出た番号はリールから即座に取り除く
- 残り1件になったら、STARTを押さずに確定させる導線を出す（回す意味がないため）

### 3-2. 賞品の開示

番号が止まった時点では、抽選画面にはまだ賞品を出さない。「賞品を見る」を押して初めて開く。

**開示演出：宝箱が震えて開く**
- 宝箱がガタガタと震える
- 一度止まる（フェイント）
- もう一度震えて、ふたが開く
- 光が広がり、賞品画像が大きく現れる

**レア度で焦らしの長さを変える**

| レア度 | 震え | 演出 |
|---|---|---|
| NORMAL | 1回 | すぐ開く |
| BIG | 2回＋フェイント | 紙吹雪 |
| MEGA | 3回＋長めのフェイント | 光が強くなり、専用ファンファーレ |

開き方の長さがレア度に連動するため、ふたが開く前から結果の大きさが伝わり、盛り上がりを作れる。

## 4. 画面構成

### 4-1. 賞品プレビュー画面

従来Googleスライドで見せていた「今日の賞品一覧」を、アプリ内で担う。

- 賞品画像をグリッドで並べ、画面共有で見せる
- **賞品番号と賞品の対応を表示する。** どの番号に何があるかを見せたうえで抽選する
- 賞品名を出すか画像だけにするかは切り替え可能とする
- 全画面表示に対応

**呼び出し方**
- 抽選画面の常設ボタン「賞品を見せる」から開く。**本番モードでも表示する**（参加者に見せるための機能であり、管理UIではないため）
- 開いている間はリールを止め、閉じると元の状態に戻る
- 閉じるボタンとEscの両方で戻れること
- 抽選中（リール回転中・開示演出中）は押せないようにし、誤操作で演出が飛ぶことを防ぐ

### 4-2. 抽選画面（メイン）

**リール**
- 画面中央に大きく配置。賞品番号が縦または横に流れる
- 停止位置を示すヒットゾーンの枠
- 残り件数の表示

**操作**
- 主操作は大きなボタン1つ。状態に応じて `START` → `STOP` → `賞品を見る` → `次へ` と変化する
- 操作者が迷わないよう、ボタンの下に次の操作を1行で表示
- そのわきに常設ボタン「賞品を見せる」を置き、いつでも賞品プレビューを開けるようにする。主操作ボタンより一回り小さくし、押し間違いを防ぐ

**キーボード操作**

| キー | 動作 |
|---|---|
| スペース | ボタンと同じ（START／STOP／賞品を見る／次へ） |
| Esc | 演出を閉じる |
| F | 本番モードの切り替え |
| P | 賞品プレビュー画面へ |

### 4-3. 賞品開示オーバーレイ

- 宝箱の開封演出
- 賞品画像を最大サイズで表示
- 賞品番号・賞品名・補足テキスト
- 「次へ」ボタン

### 4-4. 賞品リスト画面（管理）

- 番号1〜75の枠に、賞品名・画像・レア度を登録
- **当日使う賞品のON/OFF。** OFFの番号はリールに乗らない
- 画像の一括ドロップ
- 賞品の追加・削除

### 4-5. 結果画面

- 抽選順 / 賞品番号 / 賞品名 / 時刻 の一覧
- CSV書き出し（UTF-8 BOM付き）

### 4-6. 設定画面

- SE・BGMそれぞれのON/OFFと音量
- 演出の強さ（軽量化モード）
- データの書き出し／読み込み（JSON）
- 抽選結果のリセット

---

## 5. データ構造

```
賞品 = {
  番号:      1〜75
  賞品名:    テキスト
  補足:      テキスト（例「好きなの1つえらべる！」）
  レア度:    NORMAL / BIG / MEGA
  有効:      true / false（当日使うかどうか）
  画像:      1枚
  当選済み:  true / false
  抽選時刻:  日時
}
```

- 賞品の中身は空の状態から作る。初期データは投入しない
- 番号は賞品の識別子であり、参加者とは無関係

## 6. Zoom画面共有という前提

前バージョン（オフライン会場のプロジェクター投影）とは制約が大きく変わる。

### 6-1. 映像の劣化を前提に設計する

Zoomの画面共有は解像度とフレームレートが落ち、動画圧縮がかかる。

| 破綻するもの | 理由 | 対応 |
|---|---|---|
| 細かい粒子（星・塵・キラキラ） | 圧縮でノイズに潰れる | 使わない。演出は大きな面で作る |
| 暗い背景の微妙なグラデーション | ブロックノイズが最も目立つ | 明るいベタに近い背景にする |
| 高速な全画面アニメーション | フレーム落ちでカクつく | 主役1点の動きに絞る |
| 細い線・小さい文字 | つぶれて読めない | 太く、大きく |

**設計原則：明るい背景に濃い文字。要素は大きく、動きは少なく。**

### 6-2. 音声

- BGMとSEを参加者に届けるには、Zoom側で「コンピューターの音声を共有」をONにする必要がある。アプリ側では対応できないため、**起動時に一度だけ注意を表示する**
- BGMは進行の声にかぶるため、既定音量を低め（30%程度）にする

### 6-3. 本番モード

画面全体を共有すると、設定パネルや賞品リストも参加者に見えてしまう。

- 本番モードでは、リール・主操作ボタン・「賞品を見せる」ボタン・開示演出だけを表示し、管理UIを一切出さない
- 賞品プレビューは参加者に見せる機能のため、本番モードでも使えること
- 操作はキーボードのみでも完結し、画面に触らずに進行できる

---

## 7. 音

前システム「LUCKY DRAW」の音源一式をそのまま使う。

| 種別 | ファイル | 用途 |
|---|---|---|
| BGM | BGM.ogg | 常時ループ。既定音量30% |
| リール音 | normal.ogg / big.ogg | 回転中 |
| ファンファーレ | rateReelBig.mp3 / rateReelMega.ogg / rateReelSuper.ogg | 開示時。レア度で切替 |

- SEとBGMは個別にON/OFF、BGMは音量スライダー
- **音源ファイルは設定画面から差し替えられる作りにする。** 初期状態ではブラウザ内で合成した仮の音でよい

---

## 8. 画像の取り込み

- 複数の画像ファイルをドラッグ＆ドロップ
- ファイル名の数字を賞品番号として自動割り当て
- 前システムの命名規則 `LD_0001.png`（4桁ゼロ埋め）を解釈できること
- 個別差し替えも可能
- 長辺760pxに縮小して保持し、動作を軽く保つ

---

## 9. データ保存

- 賞品・画像・結果・設定を端末に自動保存し、再訪時に復元
- JSON書き出し／読み込みで、別端末への引き継ぎとバックアップに対応

---

## 10. デザイン方針

**前バージョンは黒背景の宇宙空間だった。今回は明るい方向へ全面変更する。** 会場のプロジェクターでは映えたが、Zoom越しでは暗く沈み、圧縮ノイズが目立った。

| 要素 | 方針 |
|---|---|
| 世界観 | マグナの「昼の冒険」。晴れた空の下でお祭りが始まる明るさ |
| 背景 | クリーム〜ミントの明るいグラデーション（#FFFDF6 → #DCF3EA）。ほぼベタに近く、粒子は置かない |
| 主役の数字 | 濃紺（#12245C）。明るい地に濃い文字とし、Zoom圧縮でも輪郭が残る |
| アクセント | ミント #17C29A ／ コーラル #FF5A5A ／ ゴールド #F5A623 |
| 和文書体 | Zen Maru Gothic（前システムから踏襲） |
| 数字書体 | Bungee（極太。遠目・低解像度でも読める） |
| 主役 | リールの数字と、開く宝箱。この2点に絞る |
| モーション | 回転・停止・開封に集中。背景アニメーションは置かない |

**品質の下限**
- 幅900px以下でも破綻しない
- キーボードフォーカスが視認できる
- `prefers-reduced-motion` を尊重（回転と紙吹雪を省略し、結果を即表示）

---

## 11. 対象外（今回作らないもの）

- 参加者の名簿・番号管理（参加者に番号はふらない）
- 複数端末のリアルタイム同期
- ログイン・アカウント
- 賞品の在庫管理（1賞品＝1回）
- サーバー起動（単一HTMLをブラウザで開くだけとする）
- Googleスライド・スプレッドシートとの連携

---

## 12. 要決定事項

| # | 論点 | 選択肢 |
|---|---|---|
| 1 | 「引き直す」ボタン | 本番中は隠す（推奨）／常に出す／入れない |
| 2 | 残り1件になったときの扱い | 自動確定／それでも回す |
| 3 | レア度の付与 | 賞品ごとに手で設定／全部NORMALで始める |
| 4 | 「参加者全員に！」枠 | 残す／今回はなくす |

## 付録：前システム「LUCKY DRAW ver.1.1.05」からの引き継ぎ

**活かすもの**
- 音源一式（BGM／リール音／レア度別ファンファーレ）
- 画像の命名規則 `LD_0001.png`
- 設定を1ファイルに書き出して別端末へ持っていく運用
- 抽選履歴パネルと残り回数カウンター
- 軽量化モード。**Zoom配信では既定ONを推奨**
- START／STOPの手動停止という操作感

**引き継がないもの**
- 宇宙背景一式（星3層・ネビュラ・3Dグリッド・宇宙塵・流れ星・ワープ・稲妻・画面シェイク）
- 在庫管理と「※在庫エラー」表示
- スプレッドシート連携
- Node.jsサーバー起動
- ストレステスト機能
- 2段リール構成（今回は賞品番号の1本のみ）
