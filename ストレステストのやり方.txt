========================================
  LUCKY DRAW - ストレステストのやり方（丁寧版）
========================================

ストレステストでは、抽選を何度も自動で繰り返して
「リールが消える」「当選オーバーレイが出ない」などの不具合がないか確認します。


【準備】

  1. ターミナル（コマンドプロンプト）を 2 つ開いておく
     ※ 1つ目＝サーバー用、2つ目＝テスト実行用

  2. 両方のターミナルで、lucky-draw フォルダに移動する
     例（Mac）: cd /Users/あなたの名前/Desktop/lucky-draw
     例（Windows）: cd C:\Users\あなたの名前\Desktop\lucky-draw

  3. 依存関係が入っているか確認
     次のコマンドを 1 回だけ実行しておく（未実行なら）:
       npm install
     ※ Puppeteer（Chrome を自動操作するライブラリ）が入ります。


【手順 1】サーバーを起動する

  ・1つ目のターミナルで、次を実行:

      node server.js

  ・次のように表示されれば OK:
     「LUCKY DRAW サーバー起動」
     「→ ブラウザで開く: http://localhost:8080」

  ・このターミナルはそのままにしておく（閉じない・Ctrl+C も押さない）。
     ※ サーバーが止まるとテストができません。


【手順 2】ストレステストを実行する

  ・2つ目のターミナルで、次を実行:

      npm run test:stress

  または、回数を指定する場合（例: 100回だけ）:

      PLAY_COUNT=100 node scripts/stress-play.test.js

  ※ Mac では上記のまま。Windows のコマンドプロンプトでは:
    set PLAY_COUNT=100
    node scripts/stress-play.test.js

  ・テストが始まると、画面上では Chrome が起動し、
     START → STOP → 次の抽選へ … が自動で繰り返されます。
  ・ターミナルには進捗はあまり出ず、終わるまで待ちます。
     100回なら 数分〜10分程度かかることがあります。


【手順 3】結果の見方

  テストが終わると、2つ目のターミナルに結果が表示されます。

  ・「総プレイ回数」 … 実行した抽選の回数
  ・「成功カウント」 … オーバーレイまで問題なく表示された回数
     → 理想は「総プレイ回数」と一致すること
  ・「リール空になった回数」 … リールが消えていた回数（0 が理想）
  ・「検出したバグ件数」 … 見つかった不具合の数（0 が理想）
  ・「コンソールエラー」 … ブラウザのコンソールに出たエラー数

  バグの種類の例:
    ・winner_overlay_not_shown … 当選オーバーレイが表示されなかった
    ・reel_empty_* … リールが空だった
    ・no_big_btn … スタート/ストップボタンが見つからなかった

  最後に「process.exit(bugs.length > 0 ? 1 : 0)」のため、
  バグが 1 件でもあれば終了コード 1、0 件なら 0 になります。


【うまくいかないとき】

  ・「サーバーに接続できません」
    → 手順 1 をやり直す。1つ目のターミナルで node server.js が
      動いているか、http://localhost:8080 をブラウザで開いて
      ページが表示されるか確認する。

  ・「Puppeteer が必要です」
    → 2つ目のターミナルで npm install を実行する。

  ・「address already in use :::8080」
    → すでに別の node server.js が動いている。
      1つ目のターミナルで Ctrl+C で止めるか、別のターミナルで
      動いている node を終了してから、もう一度 node server.js を実行する。

  ・テストが途中で止まる / 非常に遅い
    → 回数を減らして試す: PLAY_COUNT=10 node scripts/stress-play.test.js
    → Mac で Chrome が入っていないと Puppeteer がシステムの Chrome を
      使う場合があり、そのときは少し挙動が違うことがあります。


【小テスト繰り返し→フルテストの自動サイクル（test:cycle:mini / test:cycle:mini:full）】

  ・フルテストの前に、小テスト（100回プレイ）を繰り返し実行し、
    ログを出力、バグを検出したら修正コマンドを実行して再テスト、
    を繰り返してバグを減らしてからフルテストに進みます。

  実行（サーバーは別途起動）:
    npm run test:cycle:mini

  完全自動（サーバーも起動、寝てOK）:
    npm run test:cycle:mini:full

  環境変数:
    MINI_PLAY_COUNT=100        … 小テスト1回あたりのプレイ回数（既定 100）
    MINI_CLEAN_REQUIRED=3      … 連続で何回バグ0ならフルテストへ進むか（既定 3）
    MINI_MAX_ROUNDS=100        … 小テストの最大ラウンド数（既定 100）
    FULL_PLAY_COUNT=1000       … フルテストのプレイ回数（既定 1000）
    TEST_CYCLE_FIX="..."       … バグ検出時に実行する修正コマンド
    LOG_DIR=./test-logs        … ログ出力ディレクトリ

  ログは test-logs/mini-cycle-*.log に保存されます。


【完全自動（寝る用）】

  ・サーバーもテストも全部こちらのコマンドだけで完結します。実行したら寝てOK。

    npm run test:cycle:full

  ・既に node server.js が動いていればそれを使い、動いていなければ自動で起動してからテストします。
    終了時に「このスクリプトが起動したサーバー」だけ停止します（元から動いていたサーバーは止めません）。
  ・環境変数は test:cycle と同じ（TEST_CYCLE_MAX_ROUNDS, TEST_CYCLE_FIX, PLAY_COUNT）。


【テスト→失敗時は修正→再テストの自動サイクル（test:cycle）】

  ・ストレステストを実行し、失敗したら「修正コマンド」を実行してから再テスト、
    を最大 N 回まで繰り返します。サーバーは手順 1 のとおり起動しておいてください。

  実行:
    npm run test:cycle

  環境変数（任意）:
    TEST_CYCLE_MAX_ROUNDS=5  … 最大試行回数（既定 5）
    TEST_CYCLE_FIX="コマンド" … 失敗時に実行する修正コマンド（未設定なら修正なしで再試行のみ）
    PLAY_COUNT=100            … ストレステストの回数

  例（失敗時に lint の自動修正をかけてから再テストする場合）:
    TEST_CYCLE_FIX="npm run lint -- --fix" npm run test:cycle

  ※ 修正コマンドは「テストが失敗したとき」だけ実行されます。成功するまで、
    または最大試行回数に達するまで、テストを繰り返します。


【まとめ（やること一覧）】

  1. ターミナルを 2 つ開く
  2. 両方で lucky-draw フォルダに cd する
  3. 必要なら npm install
  4. 1つ目: node server.js を実行 → そのままにしておく
  5. 2つ目: npm run test:stress または
            PLAY_COUNT=100 node scripts/stress-play.test.js
      または 自動サイクル: npm run test:cycle
  6. 終了まで待つ
  7. 2つ目のターミナルに表示された結果を確認する
