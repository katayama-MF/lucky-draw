# 残り本数カウンターと履歴オールクリアの実装仕様

## 1. 残り本数（「残り: ◯◯本」）の算出

### 2段階モード（レートリール＋賞品リール）の場合

```
残り本数 = config.prizePool の各賞品の count の合計
```

- `prizePool`: 賞品プール（スプシから読み込み）。各要素は `{rank, name, count, imageUrl}`
- `count`: その賞品の**残り在庫数**
- 抽選のたびに `decrementPrizePoolCount()` で当選賞品の `count` を -1

### 1本リールモードの場合

```
残り本数 = config.slotAssignments.length - drawnSlotIndices.size
```

- `slotAssignments`: リールに並んだ全スロット（1本1本）
- `drawnSlotIndices`: すでに抽選済みのスロット番号の集合

---

## 2. 履歴のオールクリア（「オールクリア」ボタン）

**設計方針: オールクリア = スプシがマスター。カウンターもスプシに合わせる。**

### 処理内容

1. 確認ダイアログを表示
2. 履歴・進捗をクリア（`drawCount=1`, `drawnSlotIndices=空`, `historyEntries=空`）
3. **スプシから再取得**（`_fetchAndApplySheetData()`）
4. 取得成功時:
   - `prizePool` をスプシの内容で上書き
   - 残りカウンター = スプシの本数合計
5. 取得失敗時（オフライン等）のフォールバック:
   - 2段階モード: 履歴分を `incrementPrizePoolByNameRank` で在庫に戻す（旧仕様）
   - 残り = ローカルで計算

### オールクリア後の残り本数（スプシ取得成功時）

- **2段階モード**: 残り = スプシの各賞品本数の合計（スプシがマスター）

---

## 3. スプシ更新（「更新」ボタン）との関係

### スプシ更新時の処理

- `loadPrizesFromSheet()` → `applySheetRows()` → `applyPoolFinal()`
- スプシから読み込んだ本数を**履歴で既に引いた数だけ差し引いて** `prizePool` に反映
- `historyEntries` と `drawnSlotIndices` は**変更しない**
- オールクリア時は履歴が空のため、スプシの値がそのまま残りになる

### 2段階モードでの残り計算（賞品タブ更新時）

- 各賞品について: **残り = スプシの本数 − 履歴で当選した数**
- スプシに総数（例: 1000本）が書いてあっても、10回引いていれば残り990本と正しく表示される

### 運用のポイント

| 運用方法 | 説明 |
|---------|------|
| **スプシを「マスタ」とする** | スプシの本数＝残り在庫。スプシを更新するたびにアプリの残りはスプシの合計になる。アプリ側の抽選履歴とは別に、スプシで在庫を管理する想定。 |
| **アプリ側のみで管理** | スプシは最初の読み込みだけ使い、その後はアプリの抽選結果で count が減っていく。スプシを再度更新すると、スプシの値で上書きされ、アプリ側の進行状況はリセットされる。 |

---

## 4. データの流れまとめ

```
[2段階モード]

スプシ更新
  → prizePool = スプシの内容（count 含む）で上書き
  → 残り = prizePool の count 合計

抽選1回
  → decrementPrizePoolCount() で当選賞品の count を -1
  → historyEntries に追加
  → 残り = 減った後の prizePool 合計

オールクリア
  → 各履歴エントリで incrementPrizePoolByNameRank() により count を +1
  → historyEntries = []
  → 残り = 元の総数に戻る
```
