# これまでに発生したバグと対応（注視用メモ）

明日の朝、`npm run test:cycle:full` の結果を確認するときのチェックリストです。

---

## 1. 当選オーバーレイが出ない（winner_overlay_not_shown）

- **現象**: STOP 後、8秒待っても当選オーバーレイが表示されない。
- **原因**: リールの strip が空になったタイミングで runStop/runAlign が「idle に戻す」だけで showWinner() を呼んでいなかった。
- **対応**:
  - strip が空のときも `setTimeout(showWinner, 200)` で当選表示するように変更。
  - 停止状態から 9 秒経っても showWinner が呼ばれない場合のフォールバックタイマーを追加。
- **注視**: ストレステスト結果の「winner_overlay_not_shown」が 0 件か。

---

## 2. リールが止まった番号と当選表示の番号が違う（219 で止まって 220 が当選など）

- **現象**: リールは No.219 で止まっているのに、当選表示が No.220 になる（1つずれ）。
- **原因**:
  - 「1マスの中央」をマス幅の半分（ITEM_W/2=128）で計算していたが、実際のレイアウトは .reel-item が width:224 + margin で、**隣どうしの中心間隔は 240px**。1マス目だけ 128px のオフセットがある。
  - そのため止め位置が 16px ずれ、隣のマスが当選表示されていた。
- **対応**:
  - stopSpin で **firstCenter** と **centerStep** を DOM 実測（getBoundingClientRect）し、止め位置と getSlotIndexFromReelPos の両方で同じ基準を使うように変更。
  - showWinner ではストリップが十分あるとき「視覚／位置から得た番号」を優先するように変更。
- **注視**: 手動プレイで「止まった番号＝当選番号」になっているか。ログの「停止位置と当選計算のズレを検出」がなるべく出ないか。

---

## 3. リールが消える（strip の子が 0 になる）

- **現象**: 何度か回すとリールが消え、続けて回しても復らない。
- **原因**: buildReel / buildReelChunked のスキップ条件と他処理の競合、または「視覚と計算のずれが大きい」ときに visual を採用してしまい、strip が少ない状態のまま進んだことなど。
- **対応**:
  - buildReel のスキップ時に strip が空なら復元をスケジュール。
  - buildReelChunked の差し替えスキップ時に strip が空なら即 buildReel。
  - ensureReelVisible で「子が少なすぎる」場合も復元（expectedMin 未満なら buildReel）。
  - ずれが大きいときは視覚を信じず計算値を使用。
- **注視**: ストレステスト結果の「リール空になった回数」が 0 か。

---

## 4. NEXT 押下後にリールが中央に戻らない／ずれる

- **現象**: 「次の抽選へ」のあと、リールが止まったままの位置で表示されたり、中央がずれて見える。
- **原因**: nextDraw で buildReelChunked に渡す位置を「古い公式（ITEM_W/2）」で計算していた。
- **対応**: nextDraw では `buildReelChunked(null)` を渡し、ストリップ構築後に DOM で firstCenter を実測して `reelPos = fw/2 - firstCenter` で中央に合わせるように変更。
- **注視**: NEXT のあと、常に 1 マスがきれいに中央に来ているか。

---

## 5. スタート押す前にリールが動く

- **現象**: まだ START を押していないのにリールが動いて見える。
- **原因**: 初期化の 100ms / 400ms / 800ms で ensureReelVisible が呼ばれ、「子が少なすぎる」と判定されて buildReel が走り、位置が変わっていた。
- **対応**: 遅延 ensureReelVisible は「strip が完全に空のときだけ」実行するように変更（子が少なすぎでの再構築は行わない）。
- **注視**: ページ読み込み〜START 前まで、リールが不自然に動いていないか。

---

## 6. ストレステストで大量の exception（Node is not clickable or not an Element）

- **現象**: ストレステストで 990 件など exception が発生し、成功カウントが 1 のまま。
- **原因**: Puppeteer の ElementHandle.click() が「要素がクリック可能でない」と判定していた。
- **対応**: `page.click(selector, { force: true, timeout: 3000 })` に統一し、必要に応じて .catch で続行。
- **注視**: ストレステスト結果の「exception」件数が 0（またはごく少ない）か。

---

## 7. コンソールの 404（favicon など）

- **現象**: コンソールに「Failed to load resource: 404」が出る。
- **原因**: ブラウザが /favicon.ico を要求し、サーバーにファイルがなかった。
- **対応**: server.js で /favicon.ico に 204 No Content を返すように変更。
- **注視**: ストレステスト結果の「コンソールエラー」が 0 件、または 404 が減っているか。
