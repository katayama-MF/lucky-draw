# ストレステストで検出される問題の根本原因

## 1. winner_overlay_not_shown（当選オーバーレイが表示されない）

### 1.1 2段階モードの状態遷移

```
[ idle ]
   │  START クリック
   ▼
[ rate_spinning ]  レートリール回転中（MBIG/SBIG/BIG/HIT が流れる）
   │  STOP クリック（1回目）※ボタン有効まで 750〜1125ms
   ▼
[ rate_stopping ]  レートリール減速中
   │  減速完了
   ▼
[ rate_stopped ]   レート確定、目視 1秒
   │  onRateStopped() 実行
   ▼
[ awaiting_prize_reel ]  賞品リール待機（ボタンは「START」）
   │  START クリック（2回目）
   ▼
[ prize_spinning ]  賞品リール回転中
   │  STOP クリック（2回目）※ボタン有効まで 750〜1125ms
   ▼
[ prize_spinning / phase='decel' ]  賞品リール減速中
   │  減速完了
   ▼
[ prize_stopped ]   賞品確定、目視 1秒
   │  setTimeout(..., 1000)
   ▼
[ showing ]  showWinnerTwoStage() → winnerOverlay.classList.add('show')
```

---

### 1.2 各フェーズの所要時間（仕様）

| フェーズ | 条件 | 時間 |
|----------|------|------|
| STOPボタン有効まで | 標準モード | 1125 ms |
| STOPボタン有効まで | サクサクモード | 750 ms |
| **レートリール減速** | 最小値（標準） | 5000 ms |
| **レートリール減速** | 最小値（サクサク） | 2500 ms |
| **レートリール減速** | 距離に比例 | `ceil(2 * distance / (30*60))` ms |
| レート停止後の目視 | 固定 | 1000 ms |
| **賞品リール減速** | 最小値（標準） | 5000 ms |
| **賞品リール減速** | 最小値（サクサク） | 2500 ms |
| **賞品リール減速** | 距離に比例 | `ceil(2 * distance / (50*60))` ms |
| 賞品停止後の目視 | 固定 | 1000 ms |

---

### 1.3 賞品リール減速時間の詳細

**計算式**（script.js 2053-2055行付近）:

```
distance = |finalTargetPos - startDecelPos|  （ピクセル単位。当選スロットまでの移動距離）
spinSpeedPxPerSec = PRIZE_REEL_SPEED_MAX * 60  （= 50 * 60 = 3000 px/秒）
decelStopDuration = max(5000, ceil(2 * distance / spinSpeedPxPerSec))
```

**具体例**（centerStep ≈ 240px、賞品が10種類の場合）:

| 距離（ピクセル） | 計算 | 減速時間 |
|------------------|------|----------|
| 0 | max(5000, 0) | 5000 ms |
| 7500 | max(5000, 5) | 5000 ms |
| 15000 | max(5000, 10) | 10000 ms |
| 22500 | max(5000, 15) | 15000 ms |
| 30000 | max(5000, 20) | 20000 ms |

- 賞品リールは複数周分が並ぶため、当選スロットが遠いと `distance` が数万ピクセルになることがある。
- その場合、減速に **15〜20秒以上** かかることもある。

---

### 1.4 2回目 STOP からオーバーレイ表示までの最短・最長時間

| ケース | 内容 | 時間 |
|--------|------|------|
| 最短 | 減速最小（5秒）＋ 目視1秒 | 約 6 秒 |
| 最長 | 減速が長い（例: 20秒）＋ 目視1秒 | **約 21 秒以上** |

そのため、待ち時間を **18秒** にしても、まれに足りないケースがある。

---

### 1.5 テストがオーバーレイを待ちきれない理由

1. **2回目の START を押していない**: 1回目 STOP 後は `awaiting_prize_reel` になり、ボタンは「START」。ここで START を押さないと賞品リールが回らず、オーバーレイは永遠に出ない。
2. **減速が長すぎる**: 2回目 STOP を押した後、減速＋目視で 18秒を超える場合がある。
3. **タイミングのばらつき**: チェック間隔やマシン負荷で、ボタンが「START」になるタイミングを逃すことがある。

---

### 1.6 ストレステストの対策（実装済み）

| 対策 | 内容 |
|------|------|
| **2回目サイクル検出** | 1回目 STOP 後、3秒経過から 1.5秒間隔でボタンをチェック。テキストが「START」なら賞品リール未開始と判断し、START → STOP を実行。 |
| **基本待ち時間** | オーバーレイ表示まで最大 **18秒** 待機（環境変数 `AFTER_STOP_WAIT_MS` で変更可）。 |
| **最終リトライ** | 18秒待ってもオーバーレイが出ない場合: (1) ボタンが「START」なら START→STOP をもう1回実行 (2) いずれにせよ追加で **12秒** 待機。 |

---

## 2. 404 Not Found（コンソールエラー）

### 根本原因

アプリが読み込もうとしたリソースがサーバーに存在しない。

**想定される原因例**:

| 原因 | 説明 |
|------|------|
| BGM/SE ファイル | 設定で指定したファイルが `sound/` フォルダに存在しない |
| 賞品画像 URL | スプシやアップロードで指定した画像の URL が無効・削除済み |
| prize_pics | `prize_pics:ID` 形式で指定した画像が `prize_pics/` に存在しない |
| その他 | 存在しないパスへのリクエスト |

### テスト側の対応

- `page.on('response')` で 404 レスポンスを取得し、**どの URL が 404 か**をテスト結果に表示するようにした。
- 実行後に「404 Not Found」セクションで URL 一覧を確認できる。

### 404 の解消方法

1. テスト結果の「404 Not Found」セクションで表示される URL を確認する。
2. 該当ファイルを追加するか、設定からその URL を外す。
3. オプション（BGM など）で、なくても動作に支障がないものはそのままでも可。
